Dual Storage Architecture & Local JSON Fallback Configuration Guide

A comprehensive step-by-step technical guide on the primary MongoDB storage, automatic JSON local backup fallback, and auto-sync mechanisms.

Primary Database MongoDB Atlas
Fallback Storage data/bookings_backup.json
Email Service Nodemailer (Gmail SMTP)
Status Active & Configured

1 Executive Overview

In standard operation, all guest reservations and booking submissions are stored directly in MongoDB (Primary Storage). To guarantee zero data loss during database downtime or network disconnections, a Local JSON Fallback System has been implemented in server.js.

Key Guarantee: A booking is NEVER lost. If MongoDB fails or is unreachable, the system writes the record to local disk (data/bookings_backup.json), sends out the confirmation email, and automatically synchronizes the data to MongoDB as soon as connectivity resumes.

2 Step-by-Step Architecture Flow

STEP 1 User submits booking via Web Interface (/api/bookings)
STEP 2 Server checks MongoDB status (mongoose.connection.readyState === 1)
CASE A: ONLINE Saved directly to MongoDB → Email confirmation sent → HTTP 200
CASE B: OFFLINE Saved to data/bookings_backup.json (synced: false) → Email sent → HTTP 200
STEP 3: RECONNECT On MongoDB reconnect → Auto-sync uploads unsynced JSON records to MongoDB

3 Files & Paths

File / Directory Role Behavior
server.js Main Express Backend Contains routing, MongoDB connection, fallback writer, and auto-sync triggers.
data/bookings_backup.json Local JSON Storage File Holds records captured while MongoDB was offline. Marked with syncedToMongo: false.
.env Environment Variables Stores MONGODB_URI, GMAIL_USER, and GMAIL_PASS.

5 API Endpoints Reference

Method Endpoint Description
POST /api/bookings Receives reservations; writes to MongoDB or falls back to local JSON.
GET /api/bookings Retrieves all bookings currently stored in MongoDB.
GET /api/backup-bookings Inspects all local backup entries and count of unsynced records.
POST /api/sync-backups Manually triggers an immediate push of unsynced JSON backups to MongoDB.

6 How to Test & Verify

1. Verify Standard MongoDB Storage:

Submit a booking on the website with MongoDB connected. The server logs ✅ Booking saved to MongoDB.

2. Verify Offline Fallback Storage:

Temporarily disconnect internet or comment out MONGODB_URI in .env. Submit a booking. The server logs 📁 [FALLBACK] Booking saved to local JSON: data/bookings_backup.json.

3. Verify Automatic Sync:

Reconnect MongoDB and start the server. The server detects unsynced records and logs ✅ Successfully synced local booking(s) to MongoDB!.
